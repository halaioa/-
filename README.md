> 对应脚本：`cqooc-auto-study-v1.3.4.user.js`
>

> - 自动答题的密钥/授权门禁保持不变（那是“答”面板的边界，不是 AI 学习助手的限制）。
> **v1.3.3：取消“assist 只显示答案”的默认限制**
> 录屏里 v1.3.2 默认模式是 assist（只显示答案），所以自动运行后 AI 已作答、编辑器却是空的。
> - 新增 **“AI 作答后自动填入”** 复选框，**默认开启**：assist 也会执行填入；

> - 「填空/主观题」页签新增 **“AI 作答并填入 / 填入全部 / 停止”** 按钮，不用再切回选择题页签；
> - “填入全部”改为**填入已有答案**，不会重复请求 AI；
> - 题干提取额外过滤“← 返回列表 / 作答结束倒计时 / 当前页面值”等页面噪音；
> - 关闭“AI 作答后自动填入”后，assist 恢复只显示答案。
> **v1.3.2：修复主观题题干提取（“不能提取题目”）**
> 原因：作业页的答案容器（answer-box）与题目正文是分开的，旧逻辑在容器里取文字，
> 只拿到了工具栏“默认字号/默认字体/默认行高”和占位符，AI 以为“题目内容缺失”。
>
> 修复：新增 `aaEssayStemFromEditor()`——从富文本编辑器**往前遍历 DOM**
> （自己的前兄弟节点 + 各层祖先的前兄弟节点），过滤工具栏/占位符/按钮文字，
> 取最靠近编辑器的 3 段文本作为题干；标题（如“数智时代工匠精神的当代价值”）也会带上。
>
> 使用：更新后先点「重新提取」，再点「AI 作答」重新生成答案——
> 旧答案是基于错误题干生成的，需要重答。
> **v1.3.1：修复主观题填入后不能修改**
> 原因：平台作业富文本是 **wangEditor v5（Slate 内核，`data-slate-editor`）**。
> 旧实现直接改 contenteditable 的 textContent（还会额外 dispatch input/change），
> 绕过了 Slate 内部模型：内容能显示，但编辑器状态不同步，之后再输入无效或被回滚。
>
> 修复：
> - 优先在 DOM 祖先的 Vue 实例里找 wangEditor 实例，调用它自己的 `setHtml/insertText`；
> - 找不到就发 Slate 原生 `paste` / `beforeinput` 事件，让编辑器自己更新模型；
> - 全部方法失败时**不再强制覆盖 DOM**，保留编辑器可编辑状态，并提示点“复制答案”手动粘贴；
> - 答题列表每题新增 **复制答案** 按钮；
> - 密钥/授权门禁不变。
>
> 注意：如果编辑器里已有旧版本写入的坏内容，先刷新页面/手动全选删除，再用 v1.3.1 重新填入。
> **v1.3.0：取消题型限制，支持主观题/论述题**
> - 之前只支持选择/判断/填空，作业里的**论述题/主观题**会被当成填空，AI 只回短语；
> - 现在自动识别富文本编辑器（wangEditor `.w-e-text`、Quill `.ql-editor`、ProseMirror、
>   `contenteditable`、大 textarea 等），题型标记为**主观题（essay）**；
> - AI 提示词按题型区分：主观题要求给**完整段落**，题目有“不少于200字”等要求时写够字数；
> - 作答后把长答案写入富文本编辑器（支持 contenteditable 写入 + input/change 事件）；
> - 答题窗口的「填空」页签改为「填空/主观题」，主观题答案会显示在这里；
> - 密钥/授权门禁保持不变（这是你之前要求的限制），只是取消“题型只能选/判/填”的限制。
> **v1.2.2：修复平台视频结尾 TypeError（平台前端 bug 兜底）**
> 平台 2026-10-29 新版 `216.e904bd69.js` 的 Courseware 组件：
> data 里 `_throttleFinishLesson: null`，但 mounted 没有赋值；视频最后 5 秒 timeupdate
> 会执行 `this._throttleFinishLesson()` → `Uncaught TypeError: this._throttleFinishLesson is not a function`。
> 这是平台前端 bug，不是脚本引起的。v1.2.2 做两步兜底：
> - 检测到组件实例缺少 `_throttleFinishLesson` 时，补一个 5 秒节流的 `finishLesson` 包装；
> - 视频/音频接近结尾（`dqjd ≥ ZSC-5`）或 ended 时，主动调用平台 `finishLesson()` 上报一次，
>   避免平台自身 timeupdate 异常导致完成记录丢失。
> 平台后续修复后补丁不会生效（仅在方法缺失时补）。
> **v1.2.1：自动连播可跳转讨论区**
> - 之前 `findNext` 只选课件（LX=1），讨论区（LX=3）永远被跳过，所以“不能跳转到讨论”；
> - 现在**开启“自动回讨论”后**，自动连播会把讨论区纳入路线：
>   视频结束 → 跳转到讨论 → 自动复制首条评论并发布回复 → 继续下一节；
> - 讨论回复成功、失败、暂无内容可复制时都会继续下一节（失败等 8 秒再跳过，避免卡死）；
> - 关闭“自动回讨论”时保持旧行为：只跳课件、跳过讨论区；
> - 已回复过的讨论不会重复跳转（记录在 localStorage）。
> **v1.2.0：修复“快速连切课件 → 视频加载失败”**
> 根据录屏与面板日志定位：切课件瞬间，上一节**隐藏的 `<video>` 还在 DOM 且已 ended**，
> 旧逻辑回退使用隐藏播放器 → 误判“本节完成” → 自动连切 → 视频反复中断加载，
> 平台显示“视频加载失败”。
>
> 修复：
> - `findMedia()` 只使用**可见**播放器，不再回退隐藏旧播放器；
> - 视频完成判定加 **3 秒冷静期**，且要求本课件**实际播放过**（timeupdate 记录）；
> - 平台进度（dqjd ≥ ZSC-5）必须同时有“本课件实际播放”的证据；
> - **频繁切换保护**：60 秒内切 5 次自动暂停自动下一节 2 分钟，并提示 Alt+V；
> - 诊断/错误码/Alt+V 与 v1.1.9 相同；仍失败时先关闭“卡住刷新”再手动刷新。
> **v1.1.9：视频加载失败排查**

## 安装

1. 打开 `cqooc-auto-study-v1.3.4.user.js`，复制全部内容；
2. 在 Tampermonkey 里新建脚本，粘贴覆盖，`Ctrl+S` 保存；
3. 进入课程学习页或答题页，右下角出现“重庆高教 · 自动学习”面板即安装成功。

如果已安装旧版本：直接在 Tampermonkey 中替换脚本内容即可，旧版本归档目录不受影响。

## 一、自动学习（沿用 v1.0.8）

| 功能 | 说明 |
| --- | --- |
| 自动播放 | 进入课件后自动播放视频/音频 |
| 倍速/静音 | 1× / 1.5× / 2×，默认静音，便于通过浏览器自动播放策略 |
| 自动下一节 | 当前课件完成后自动切到下一节 |
| 补齐漏课 | 优先补目录中最早未完成的课件 |

| AI 学习助手 | 解释课件、总结重点、回答讨论题（考试/测验页禁用） |

快捷键：`Alt+S` 开始/暂停，`Alt+N` 下一节，`Alt+D` 诊断，`Alt+A` 打开答题面板。

## 二、AI 自动答题（v1.1.5 可拖动窗口）

### 0. 打开与布局

- 点主面板顶部 **“答”** 或按 `Alt+A` 打开答题窗口；
- 窗口**可拖动**（按住标题栏拖动，位置会记住）；右上角 `−` 收起、`×` 关闭；
- 三个二级菜单：
  - **选择题/判断题**：单选、多选、判断；每题显示原题号；
  - **填空题**：填空/简答题；同一题目的多个空会显示“第 3 题（第一【】）”等；
  - **设置/测试**：模式、授权、AI 配置、高级选择器、提交、导出证据、日志；
- 每道题点开后显示“**填入本题**”，也可以整页“AI 作答 / 填入全部”；
- 窗口不遮挡页面，答题时页面仍可正常点击、滚动。


### 1. 第一次配置

- 打开答题窗口 → 切到 **设置/测试**；
- 填 **API 地址 / 模型 / API Key**（与 AI 学习助手共用同一份配置）；
  默认地址 `https://api.deepseek.com/chat/completions`，默认模型 `deepseek-chat`；
- API Key 只保存在本机浏览器 localStorage，不写日志、不导出；
- 需要在“设置/测试”里输入 **授权密钥** `114514` 并按回车/失焦：状态显示
  “密钥验证通过：答题功能已解锁”，授权自动勾选并持久保持；
- 未验证前答题按钮是禁用的，无法使用 AI 作答/填入/提交；
- 勾选 **“固定当前答题模式”** 后，模式下拉框会锁定为当前选择（刷新后仍保持）；
  需要换模式时先取消固定；
- 取消勾选“我确认…”会立即重新锁定答题功能，需要重新输入密钥。

### 2. 三种模式

| 模式 | 行为 | 是否写页面 | 需要授权确认 |
| --- | --- | --- | --- |
| `assist`（默认） | 提取题目 → AI 作答 → 在面板里显示答案 | 否 | 否 |
| `fill` | 在 assist 基础上把答案填入页面选项/输入框 | 是 | 是 |
| `submit` | 在 fill 基础上点击页面自己的“提交/交卷”按钮 | 是 | 是 |

- 模式在下拉框里切换；`fill` / `submit` 需要勾选
  **“我确认：当前仅在已获书面授权的测试环境使用自动填答/提交”**；
- 该确认只保存在内存里，**刷新页面后自动失效**，需要重新勾选；
- 生产域名 `www.cqooc.com` 会在面板顶部显示红色警告。

### 3. 使用流程（独立答题页：测验 / 作业 / 考试）

1. 打开答题页；
2. 按 `Alt+A` 打开答题面板，确认顶部显示“页面：测验/作业/考试”和识别到的题目数；
3. 想先看答案：点 **“提取题目”** → **“AI 作答”**（assist 模式）；
4. 确定要测试自动填答：切到 `fill` → 勾选授权确认 → 点 **“填入答案”**；
5. 确定要测试自动提交：切到 `submit` → 勾选授权确认 → 点 **“提交（需授权）”**；
6. 测试结束点 **“导出证据”**，会下载
   `cqooc-anti-cheat-evidence-<时间>.json`，同时尝试写入剪贴板。

### 4. 视频弹题

- 课程学习页出现弹题（“请先回答/请作答后继续”之类）时：
  - `assist`：AI 答案显示在答题面板，弹题不自动点；
  - `fill` / `submit`：先勾选授权，脚本会自动选答案并点弹题里的“确定/继续”；
- 如果没配置 API Key，弹题保持旧行为：响一声 + 标题提醒，由人工作答。

### 5. 识别不到题目怎么办

v1.1.2 已适配真实答题页的自定义 div 选项与多空填空。仍然识别不到时，按下面顺序处理：

1. 打开答题面板点 **“提取题目”**，看题目数是否为 0；
2. 点 **“结构快照”**：会在控制台打印、并复制到剪贴板、同时下载
   `cqooc-page-structure-时间.txt`。v1.1.2 的快照里包含：
   - 每个文档/iframe/shadow root 里 radio/checkbox 数量、**识别到的选项节点数 optionNodes**；
   - **提取结果 extract=数量 types=题型**，以及前 8 道题的题干（Q1/Q2/...）；
   - 每个识别到的选项节点 O1/O2/... 的 class 与文本；
   - 文本输入框、题目容器候选 class、选项区域 HTML 片段（已去除脚本/样式）；
3. 把这份快照文本发给开发者，或在答题面板 **“高级：自定义 CSS 选择器”** 里手动填写：
   - 题目容器：每题外层容器的选择器；
   - 选项组 / 选项 / 题干：对应节点选择器；
   - 提交按钮：找不到提交按钮时填；
4. 也可以在控制台执行 `window.__CQOOC_AA__.dump()` 查看识别到多少选项/题目；
5. 填完会自动保存，下次进入页面继续生效；点“提取题目”复验。
6. 如果结构快照里只有 `iframes: N` 和空的 radio/checkbox，说明题目在**跨域 iframe** 里：
   浏览器同源策略禁止父页面读取，需要在 iframe 对应域名上单独注入脚本（去掉 `@noframes`），
   或在开发者协助下加新的 `@match`。

## 面板和弹窗全都没有 / 脚本没运行（v1.1.4）


如果**浮动面板、右下角“答”、所有弹窗都不出现**，且控制台执行
`window.__CQOOC_AA__.uiCheck()` 报 “Cannot read properties of undefined”，
说明 **userscript 根本没注入到当前考试页**，不是弹窗代码问题。按顺序检查：

1. **确认脚本已启用**：点浏览器 Tampermonkey/篡改猴扩展图标，确认
   “重庆高等教育智慧教育平台 · 自动学习助手（答题测试版）”在里面且为**启用**状态；
2. **安装/更新脚本后必须刷新页面**：修改脚本不会热更新已打开的标签页。
   在考试页按 `Ctrl+Shift+R` 强制刷新，或**关闭考试标签重新进入考试**；
   如果考试页是从“开始答题”弹窗新开的标签，安装脚本后要关掉重新开；
3. **刷新后先看控制台**：
   - 出现 `[CQOOC助手] userscript 已注入 v1.1.4（stage=boot）` → 脚本已注入；
   - 执行 `window.__CQOOC_US__`，正常应返回 `{stage: "ready", aaReady: true, ...}`；
   - 若返回 `undefined` → 脚本仍未运行，继续第 4 步；
4. **确认脚本内容完整**：在 Tampermonkey 编辑器打开脚本，检查：
   - 开头有 `// ==UserScript==`，结尾有 `// ==/UserScript==`；
   - 文件末尾是 `})();`（v1.1.4 全文约 5000+ 行）；
   - 编辑器没有红色语法报错提示；
   如果复制粘贴可能漏内容，建议直接**打开本地 .user.js 文件触发 Tampermonkey 安装**，不要手动粘贴；
5. 检查 Tampermonkey 设置：该脚本没有被“排除/仅特定页面”限制，
   浏览器没有禁用扩展、没有无痕模式限制。

> 关键判断：`window.__CQOOC_US__` 是脚本注入后**第一行**就写入的标记。
> 它不存在 = 脚本没运行，和答题弹窗、题目识别都无关。

## 答题窗口打不开 / 看不清（v1.1.3 起）

> v1.1.5 起答题窗口是可拖动浮窗，不再用全屏遮罩；如果仍然看不到：


按顺序试：

1. **找右下角圆形“答”按钮**：答题页会自动出现，点击即可打开答题弹窗（和面板顶部的“答”是同一个弹窗）；
2. 按 **`Alt+A`** 也可以打开/关闭答题弹窗；
3. 打开 `F12` 控制台，执行：

   ```js
   window.__CQOOC_AA__.uiCheck()
   ```

   会输出面板/弹窗状态，重点看：
   - `hostAttached`：浮动面板是否还在页面里（false = 被平台重渲染移除，脚本会自动挂回）；
   - `hasShadow` / `hasButton`：面板的 Shadow DOM 与“答”按钮是否存在；
   - `maskShown` / `maskDisplay`：弹窗是否加上了 show、计算后的 display；
   - `maskParent`：弹窗挂在 `shadow` 还是 `body`（body 表示已走页面级兜底）；
   - `fallbackUsed` / `fallbackStyle`：是否用过兜底、兜底样式是否注入成功；
   - `fullscreen`：页面是否处于全屏状态（全屏时弹窗会挂到全屏元素下）。
4. 如果 `maskShown=true` 但仍看不到弹窗，把 `uiCheck()` 输出和 `F12` 红色报错截图发给开发者；
5. 还可以在控制台直接执行：

   ```js
   window.__CQOOC_AA__.open()          // 强制打开答题弹窗
   window.__CQOOC_AA__.mountFallback() // 强制切换为页面级挂载
   ```

## 视频加载失败怎么办（v1.2.0 优先看这里）

> **v1.2.0 已修复“快速连切”导致的视频加载失败。** 如果更新后仍失败，按下面步骤继续排查。


平台播放器在进度条上方显示“视频加载失败”时，先区分是**平台/网络问题**还是**脚本影响**：

1. **按 `Alt+V`** 打开视频诊断（或控制台执行 `window.__CQOOC_AUTO_STUDY__.videoDiag()`），
   控制台会输出并复制一份 JSON，重点看：
   - `error.code`：2=网络错误、3=解码错误、4=源不支持/加载失败；
   - `readyState`（0=没有数据）、`networkState`（3=无源）；
   - `src` / `protocol`：视频源地址与协议（http/https）；
   - `recoverCount`：脚本已自动刷新次数；
   - `lastMediaError`：最近一次错误的 code/message/src。
2. **先关闭“卡住刷新”**：主面板取消勾选“卡住刷新”，再手动 `Ctrl+Shift+R` 刷新页面。
   如果关闭后视频能正常加载，说明是自动刷新在反复打断视频源加载。
3. **换网络/浏览器验证**：用手机热点或另一个浏览器打开同一课程；
   如果都一样失败，基本是平台视频 CDN/资源问题，不是脚本。
4. **彻底排除脚本**：在 Tampermonkey 里临时关闭本脚本并刷新；
   视频仍失败 → 平台/网络问题；视频恢复 → 把 `Alt+V` 的诊断 JSON 发给开发者。
5. 错误码 4 时 v1.1.9 已**不再自动刷新**，只会提示，避免“刷新→再失败”的循环。

## 三、失败原因排查

### 1. 面板完全没有出现

- 确认 Tampermonkey 已启用脚本、当前 URL 匹配 `https://www.cqooc.com/*`；
- 刷新页面看控制台是否有 `[CQOOC助手]`、`[CQOOC答题]` 日志；
- 如果页面在 iframe 里，脚本默认 `@noframes` 不运行，需要在主框架打开。

### 2. 面板显示“请进入课程学习页面”

正常。自动学习只在 `/course/detail/courseStudy` 生效；答题页会显示“答题页 · 测验/作业/考试”。

### 3. 答题面板显示“没有识别到题目”

- 确认题目已经加载完（有的页面先出骨架屏）；
- 用 `window.__CQOOC_AA__.dump()` 看页面结构，按上一节“自定义选择器”修正；
- 也可能是题目在 iframe 内，需要把 `@noframes` 去掉单独注入（不建议同时开多个实例）。

### 4. AI 作答报“网络/CORS 错误”

- 接口必须允许浏览器跨域（OpenAI 兼容接口通常可以；自建代理需带 CORS 头）；
- 检查 API Key 是否有效、额度是否充足、模型名是否正确。

### 5. 填入失败但 AI 有答案

- AI 可能返回了选项文本而不是字母，脚本会自动按文本匹配；仍失败时看 `fillReport`；
- 页面选项可能被禁用（例如已经交卷、时间到），脚本会记录为失败；
- 可在控制台执行 `window.__CQOOC_AA__.state.fillReport` 查看每题状态。

### 6. 提交按钮找不到

- 在“高级：自定义选择器”里填提交按钮选择器；
- 或用 `window.__CQOOC_AA__.findSubmit()` 在控制台确认是否找得到。

### 7. 最小化/切到后台就不走了

浏览器会节流后台定时器。用归档目录里的“启动刷课Edge”脚本启动 Edge，或保持窗口可见。

## 五、边界与风险

1. 默认 `assist`：只读页面 + 显示答案，不修改页面；
2. `fill` / `submit` 需要每次会话手动授权确认，脚本不保存授权状态；
3. 脚本只做页面级点击/输入，不直接调用平台私有接口伪造答题记录，
   不隐藏、不绕过平台前端校验（包括计时、切屏、人脸识别等平台自身机制）；
4. 平台可能通过答题时长、操作节奏、内容差异、请求特征等方式检测自动化行为，
   本脚本只负责记录可观察到的证据，不保证不被检测；
5. 生产环境自动答题/提交可能违反平台用户协议和学术诚信要求，
   **请只在已获授权的测试环境使用，风险自负**。
